# wuji-tools 憲章

## Core Principles

### I. 雙視埠交付前自檢（NON-NEGOTIABLE）
任何功能、頁面、樣式或資料更新，在標記完成或發布前，必須在 390px（手機）與 1280px（桌機）兩種視埠，實際檢查版面配置並操作功能。未完成兩項自檢者，不得交付。

理由：本專案直接發布至 GitHub Pages，無建置程序與自動化測試關卡；人工雙視埠自檢是防止版面破碎與功能失效的必要屏障。

### II. 供應鏈來源限制（NON-NEGOTIABLE）
禁止引入任何中國關聯 GitHub repo 的依賴套件、程式碼片段、素材或全域資源。新增第三方資源前，必須確認其 repo 與維護者非中國關聯。

理由：降低地緣政治與法規風險造成的不可用或合規問題，並維持供應鏈可控。

### III. 資料真實性與來源標示（NON-NEGOTIABLE）
不得捏造數據。所有對外呈現的數據必須具備可查證來源（公開資料、官方 API 等），或在介面上明確標示為「示意」。

理由：本站提供記帳、股市、庫存等資訊，錯誤或虛構數據會直接誤導使用者。

### IV. 繁體中文（台灣）介面
所有使用者介面文字、標籤、提示、錯誤訊息與隨附文件，一律使用繁體中文（台灣），不得混用簡體中文。

理由：目標使用者為台灣受眾，一致的語言風格是可讀性與信任的基礎。

### V. 機密資訊零寫入（NON-NEGOTIABLE）
不得在程式碼、版本控制提交（commit）或任何輸出中寫入密碼、API 金鑰、權杖或驗證碼。機密資訊必須透過外部機制（如環境變數或伺服器端設定）提供。

理由：本專案原始碼公開於 GitHub 倉庫，任何寫入的機密等同於公開洩漏。

### VI. 追蹤器單一化
數據追蹤僅得使用 GoatCounter，不得加入 Google Analytics、其他分析服務或任何額外追蹤器。

理由：維持最小資料蒐集與可預測的隱私影響，並與現有首頁實作一致。

## 技術與部署約束
本專案為 GitHub Pages 靜態工具站，僅使用純 HTML、CSS 與瀏覽器端 JavaScript，無建置步驟。所有頁面必須能直接以靜態檔案發布；不得引入需要伺服器端執行、套件安裝或編譯的依賴。新增工具頁面應沿用既有目錄結構與首頁導覽模式，並維持 `lang="zh-Hant-TW"` 設定。

## 交付工作流程與品質關卡
每次變更必須依序通過下列關卡，任一關卡未通過即不得交付：

1. 實作：遵循前述六項原則。
2. 版面與功能自檢：於 390px 與 1280px 視埠實際操作並確認無異常。
3. 資料查核：確認每筆數據具可查證來源或已標示「示意」。
4. 機密掃描：確認程式碼、commit 訊息與輸出不含密碼、金鑰或驗證碼。
5. 追蹤器確認：僅保留 GoatCounter。

## Governance
本憲章為 wuji-tools 所有開發與交付決策的最高準則；與其他實務文件衝突時，以本憲章為準。修訂必須提出變更說明、列出受影響原則，並依語意化版本規則更新版本號：MAJOR 為移除或重新定義原則、破壞性治理變更；MINOR 為新增原則或章節、實質擴充指引；PATCH 為文字澄清、錯字修正或非語意調整。所有提交與審查必須驗證上述原則遵循情況，任何例外須明確記錄並經核准。
